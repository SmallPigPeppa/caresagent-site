系统设计

生命周期与执行链

Project、Session、Turn、Run 各自管理明确的状态；Run 内由 Agent 组合上下文、Tool 与 Skill，Policy 逐调用判定、Approval 处理 ask，再把类型化 Event 投影成 Timeline。

从 Project 到 Timeline

Project → Session → Turn → Run；Run 内由 Agent 结合上下文与 Skill 调用 Tool，Policy 对每次调用做 allow / ask / deny，Approval 只处理 ask，类型化 Event 最终投影为 Timeline。

Project工作区 + 配置
Session历史 + 权限
Turn一次用户请求
Run一次执行尝试
Agent上下文 + Skill
Tool类型化调用

Approval仅 ask 等待

一个 Run 可因 ask 阻塞，并在批准或拒绝后恢复，也可被取消；结算状态写回 Session。

各个组成部分

对照上图逐一说明。

Project 拥有工作区与项目配置；Session 持久保存对话、权限和已启用 Skill；一条用户消息形成一个 Turn；一次具体执行是一个 Run。Run 可以执行、因授权而阻塞、恢复或取消，结算后再把结果写回 Session。

Agent 进行模型推理，由运行时注入上下文、可用 Tool 与 Skill。Skill 提供指令和资源。每个 Tool 调用都会由 Policy 根据 ToolDefinition、参数、会话模式与规则给出 allow / ask / deny；只有 ask 才进入 Approval 等待用户决定。

执行过程发布模型、工具、权限、进度、产物、对外动作与生命周期等类型化 Event。事件追加到会话 trace，再由确定性 reducer 投影成 Timeline，通过 API / SSE 提供给客户端。开发态写入根目录 .caresagent/，打包态写入操作系统用户数据目录；内置配置与 Skill 从 backend/resources/ 只读加载。

Tool 层

Tool 是带稳定定义的可执行能力，由定义、目录、解析与执行四个部分组成。

ToolDefinition

声明一个 Tool 的稳定描述：名称、分组、参数与副作用标识，以及并发与中断语义。

Tool Catalog

对全部 Tool 定义做一次性索引，用于发现与诊断。

Tool Resolver

每个 Turn 根据配置与运行上下文构建当次可用的工具集。

Tool Executor

校验处理器，并把同步与异步调用收敛到同一入口执行。

文件与工作区

文件类 Tool 在项目工作区内读写；工作区之外的配置路径为只读。

文档 + 媒体

Office 文档生成、PDF 解析与渲染、视觉理解与 CL-OCR 识别。

网络采集

网页搜索与浏览、结构化文章采集、文件下载。

产品能力 · CAIR AI 资讯

把整理好的文章内容与配图组合成 HTML 页面和可编辑的 Word 文档。

平台集成

公众号发布、企业微信与个人微信发送、腾讯会议、打印。

Policy + Approval

Policy 为每次调用给出 allow / ask / deny；ask 时暂停执行，待 Approval 决定后继续。

Skill 层

可加载的指令与资源

Skill 是可加载的指令与资源包：启用后随会话保存，执行时把说明注入智能体上下文。

已内置 5 个：

cair_ai_news · paper_doc · paper_ppt · pdf_screenshot · wechat_draft_box

设计原理

四层生命周期

Project 管工作区与配置，Session 管持久会话状态，Turn 对应一条用户消息，Run 对应一次可阻塞、恢复或取消的执行尝试。

Agent / Tool / Skill 分层

Agent 进行推理，Tool 执行操作，Skill 提供可加载的指令与资源；三者独立演进、独立测试。

逐调用 Policy / Approval

ToolDefinition、实参、会话模式与规则共同产生 allow / ask / deny；只有 ask 进入用户批准流程并支持恢复。

类型化 Event → Timeline

运行时发布类型化 Event，先追加到会话日志，再由确定性 reducer 投影成 Timeline；客户端消费投影，不重做领域判断。

状态与资源分离

运行数据保存在应用数据目录；内置配置与 Skill 随安装包提供。

一个 API，多端适配

caresagent.api.app:app 是唯一 ASGI 组合入口；桌面端与消息渠道复用同一套应用服务、Policy 和 Event 契约。
